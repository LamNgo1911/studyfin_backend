## Decisions Made
- Used `@keyv/redis` adapter instead of `cache-manager-redis-store` — the latter is incompatible with `@nestjs/cache-manager` v3+
- Created GIN indexes via raw SQL (`CREATE INDEX ... USING GIN (to_tsvector(...))`) instead of Prisma `@@fulltext` PSL directive — Prisma 7's config-based datasource mode does not support the `@@fulltext` directive in schema PSL parsing
- Removed `url` from datasource block entirely — Prisma 7 config-based mode uses `prisma.config.ts` for connection URL; adding `url = env(...)` in the schema file causes a P1012 validation error
- Used `ConfigModule.forRoot({ isGlobal: true })` so ConfigService is available throughout the app without re-importing
- Cache TTL set to 24h for default cache behavior matching plan's "repeat API requests within 24 hours are served from Redis cache" requirement

- **Found during:** Task 2 (Schema validation / db push)
- **Issue:** Prisma 7 with `prisma.config.ts`-based datasource does not support the `@@fulltext` PSL attribute. - **Fix:** Kept `previewFeatures = ["fullTextSearchPostgres"]` in generator for client type generation. Created GIN indexes via raw SQL with `to_tsvector('english', ...)` for equivalent full-text search indexing. Created `prisma/create-fulltext-indexes.sql` for reproducibility.
- **Files modified:** prisma/schema.prisma, prisma/create-fulltext-indexes.sql (new)
- **Verification:** `psql` confirmed both indexes exist: `Program_name_description_fts_idx` and `University_name_description_fts_idx` using GIN on `to_tsvector('english')`
