<objective>
Fix the universities endpoint to return language-appropriate names and descriptions instead of the single-language-resolved data currently stored during sync.

Purpose: When a user passes `lng=en` (or any language code) to the universities endpoint, the response should contain name/description text in that language. Currently, the sync service resolves multilingual Opintopolku data to a single language at sync time (preferring English, falling back to Finnish), making it impossible to dynamically serve the correct language at query time.

Output:
- University schema with `nameMultilingual` and `descriptionMultilingual` Json columns
- Sync service that stores full multilingual data for universities
- Universities service that resolves names/descriptions based on `lng` parameter
- Downstream consumers (ProgramsService, SearchService) that resolve university names with English default
- Updated unit tests
</objective>

    **2a. Create shared resolveLang helper** (`src/modules/universities/universities.service.ts`):

    Add a static/private helper method to UniversitiesService (before the existing private methods):

    ```typescript
    private resolveLang(data: any, lng: string): string {
      if (!data) return '';
      if (typeof data === 'string') return data; // backward compat with old single-language data
      if (typeof data !== 'object') return String(data);
      return data[lng] ?? data.en ?? data.fi ?? '';
    }
    ```

    This handles three cases:
    1. `data` is null/undefined — return empty string
    2. `data` is a plain string — return as-is (old data migrated as string-to-JSON or legacy single-language data)
    3. `data` is a multilingual object — resolve by `lng`, fallback to `en`, then `fi`, then empty
